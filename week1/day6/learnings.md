# Day 6 Learnings

## What I Learned
- I learned how to structure technical documentation so it is clear, consistent, and easy to maintain.
- I learned how to write a full system architecture document, including principles, tech stack, components, data flow, security, performance, deployment, and monitoring.
- I learned how to create Mermaid-based UML/architecture diagrams and sequence diagrams for API and real-time WebSocket flows.
- I learned how to write API documentation with endpoint details, parameters, request/response examples, error formats, and rate-limit notes.
- I learned how sprint planning works in Agile, including user stories, acceptance criteria, story points, sprint capacity, goals, and Definition of Done.
- I learned how reusable documentation templates help speed up future work and improve consistency across files.
- I learned to check Markdown rendering issues, especially nested code fences in template documents.

## Skills I Improved
- Technical writing
- System thinking and architecture communication
- API design communication
- Agile planning and estimation
- Documentation formatting in Markdown and Mermaid

## Key Takeaways
- Good documentation is as important as code for team collaboration.
- Visual diagrams make architecture and data flow easier to understand.
- Standard templates reduce confusion and save time in future tasks.

## Next Time I Will
- Start with a documentation checklist before writing.
- Validate preview rendering earlier.
- Keep all docs grouped by purpose from the start.
